# Upstream review notes for the Void Linux port

The [hybrid arrangement in issue #155](https://github.com/liixini/skwd-wall/issues/155#issuecomment-6547549776) leaves Void Linux maintenance and packaging with **SirOtter0**. The upstream maintainer can review and integrate any suitable pieces in Skwd-release. No change to Skwd's upstream source or release process is required for the published XBPS packages.

The four packages are coordinated for **Void Linux x86_64 glibc with runit**. They install no autostart or systemd service; leaving session start under the user's control also keeps Niri and Noctalia configuration outside the package. The Void VM tests covered install, update, removal and rollback. The public HTTPS install used an authenticated local snapshot and passed `xbps-pkgdb -a`. Wall beta29_2 opened and rendered on Niri/Wayland with NVIDIA RTX 4060 Ti; the user confirmed general visual operation. This validation is scoped to the tested driver, device and features.

The archived source records original port commit `08e344a7bf2518aba18f84eebd04f8e66525abae`, with the local release validation ending at `f444402a79bec8c264fd8d52a3166fd104cb9a10`. The public handoff carries the relevant beta29_2 files at their archived SHA-256 values, based directly on upstream beta.29. The [signed beta29_2 release](https://github.com/SirOtter0/skwd-void-repo/releases/tag/xbps-beta29_2) remains the distribution source.

For Skwd-release, the useful parts to review are the isolated component builds, the XBPS package and dependency layout, the private FFmpeg preparation and the Void VM validation. The signed publication workflow, key management and external package hosting stay with the Void port. Use [the XBPS issues tracker](https://github.com/SirOtter0/skwd-void-repo/issues) for Void-specific reports.
